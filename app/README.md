# Prism

Локальная панель для ComfyUI v0.34.0. Поддержанный и проверенный путь: SDXL checkpoint → LoRA/персонаж → txt2img или img2img → Hires → ReActor → FaceDetailer → финальный апскейл → SaveImage. Этапы опциональны. Anima исключена из текущего пайплайна.

## Запуск и обновление

Запуск: `D:/AI/Prism/Prism.bat` или `./Start.ps1` из этой папки. Панель остаётся на http://127.0.0.1:8188/dashboard/ .

Пути ComfyUI, Python и моделей, порт и параметры запуска находятся в `prism.json`. Относительные пути отсчитываются от этой папки; `model-paths.json` задаёт категории моделей. ComfyUI подключает приложение через `custom_nodes/prism`, указывающий сюда. Matrix не участвует в запуске.

`./Start.ps1 -Action Status` проверяет готовность. `-Action Stop` останавливает только настроенный ComfyUI при пустой очереди. `-Action CheckUpdate` проверяет стабильный релиз; `-Action Update` обновляет остановленный backend, предварительно проверяя Git, совместимость зависимостей и создавая резервную копию в `.cache/updates`. При ошибке установки запуск блокируется маркером в `.cache/runtime`. Инструкция восстановления — в `../README.md`.

Повторный запуск не создаёт второй процесс. Журнал backend и PID находятся в `.cache/runtime`. Открытие браузера можно отключить флагом `-NoBrowser`. BAT после запуска показывает живые stdout и stderr через `Show-Logs.ps1`; просмотр можно закрыть без остановки backend. Для остановки используется `Start.ps1 -Action Stop`.

## Персонажи

В блоке «Активный персонаж» выбираются сохранённый образ, вес LoRA и комплект одежды; одежду можно отключить. Настройка связанного с LoRA образа открывается в библиотеке. Персонажи без LoRA сохраняют отдельный редактор.

В библиотеке откройте LoRA персонажа → «Настроить персонажа»: редактор встроен в тот же попап рядом с превью. Сохранение и отмена возвращают к сведениям LoRA; закрытие попапа сбрасывает несохранённый черновик. Задайте имя образа, отметьте нужные авторские кейворды и добавьте их в основу образа или выбранный комплект одежды. Оба описания можно редактировать вручную; комплекты можно создавать, переименовывать и удалять. «Сохранить» записывает образ, «Использовать» делает его активным. До сохранения изменения остаются черновиком. Для одной LoRA можно сохранить несколько образов; существующие записи доступны сразу. «Персонаж без LoRA» в библиотеке создаёт независимую запись. Удаление образа не удаляет файл LoRA. На телефоне редактор расположен в один столбец.

Общая база для всех браузеров хранится в `data/characters.json` рядом с этим README. Предыдущая версия — `data/characters.json.bak`. При переносе установки скопируйте папку `data`; она исключена из Git. В JSON сохраняются имена, описание, LoRA и её вес, комплекты одежды и выбранный комплект. Пресеты моделей также хранятся в папке `data`; текущая форма и история — в браузере.

При отсутствии файла панель один раз импортирует `comfy_characters` из браузера, открывшего её первым; исходные браузерные записи не удаляются. Заполненный серверный файл не заменяется браузерной базой. Старые записи с другой системы требуют отдельного переноса из её браузера.

Запись выполняется через временный файл с атомарной заменой. Повреждённый JSON не заменяется пустой базой; ошибка видна в блоке персонажей. При конфликте между вкладками сохранение отклоняется — обновите страницу, чтобы загрузить новую версию. Для ручного редактирования или восстановления файла остановите ComfyUI, замените JSON, запустите сервер и обновите вкладки.

Для доступа только с компьютера задайте пустой `lan_interface` в `prism.json` и перезапустите backend при пустой очереди. Правила Windows Firewall не изменялись.

## Мобильная панель

При ширине до 1100 px доступны два экрана: «Генерация» с промптами, результатом и историей, и «Параметры» с моделями, персонажами, LoRA и дополнительными проходами. Запуск, остановка и статус находятся в нижней закреплённой панели. Передача результата в Img2Img открывает параметры, запуск возвращает к генерации. При увеличении окна элементы возвращаются в настольную раскладку без потери введённых значений.

HTTP-доступ по LAN поддержан через `crypto.getRandomValues` там, где браузер не предоставляет `crypto.randomUUID`. Копирование триггеров по HTTP открывает оформленный диалог панели с текстом для ручного копирования, если Clipboard API недоступен. Запросы названий, подтверждения удаления и уведомления также используют диалоги панели; Escape отменяет действие.

`Start.ps1` направляет поддержанные кэши Python/uv/pip/Hugging Face/Torch/Ultralytics в `.cache` панели. Кэш ComfyUI-Manager остаётся в штатном `ComfyUI/user/__manager/cache` — этот скрипт его не перенаправляет. Браузерная проверка использовала временный профиль agent-browser в `%USERPROFILE%/.agent-browser`; npm и скриншоты направлены в проектную `.cache`.

## Что исправлено

- `compileWorkflow(settings)` не читает DOM или localStorage. Clip skip действительно включает `CLIPSetLastLayer`; нулевые CFG/denoise/seed сохраняются, ID LoRA не пересекаются с ReActor.
- Каталог строится по `/object_info`, поддерживает старые списки и новые `COMBO/options`. Отдельные diffusion models не выдаются за checkpoint; недоступные узлы, веса и значения останавливают отправку с объяснением.
- `ComfyClient` владеет заданием: неизменный снимок, стабильные client/prompt ID, адресная отмена, ошибки HTTP, восстановление через history/queue. Сетевая ошибка POST не вызывает повторной отправки.
- Завершение подтверждается `/history/{prompt_id}`, файлы берутся только из конечных SaveImage своего графа. Чужие события исполнения не завершают задание панели.
- История сохраняет отправленные настройки, граф и фактические outputs. «Повторить» отправляет этот граф; «Параметры» восстанавливает форму. Старые записи без графа доступны для просмотра, точный повтор для них отключён.
- Кнопка ✨ использует выбранный файл, увеличивает его и выполняет img2img. Для серии сначала выбирается кадр. Уже выполненные ReActor/FaceDetailer/финальный апскейл повторно не включаются. Масштаб, denoise и апскейлер берутся из текущих соответствующих настроек; остальной рецепт — из выбранной записи.
- Новые серии 1/4/9 состоят из независимых кадров с известными seed. Сетка помещается целиком в предпросмотр и скачивается одним PNG. У старых записей без параметров отдельных кадров показан только seed серии; копирование seed отдельного кадра отключено.
- Промпт в lightbox выводится как текст; Blob URL освобождаются. Веб-маршрут не раздаёт `.git`, `.cache`, Python и PowerShell-файлы.
- Циклы импортов устранены; Python-сервер читает метаданные LoRA в рабочем потоке. Частотность тренировочных тегов больше не выдаётся за список trigger words.

Исторические диагностические файлы ниже остались в прежнем каталоге `ComfyUI/custom_nodes/comfyui_dashboard/.cache`. Актуальные проверки Prism — в `PRISM_VERIFICATION.md`.

## Причина шума и восстановление модели

Старый `novaKemonoXL_v80.safetensors` имел правильный размер, но неверный SHA256: `2169c16086adf32e650b5dee905dbb87d722f72a3fd5eef645ef0b47918c67ab`. При сравнении с оригиналом отличались 1471 тензор UNet; в проверенных участках веса были заполнены нулями. VAE совпадал и успешно восстанавливал готовую тестовую фотографию. Поэтому сервер мог завершать задания без исключений, выдавая шум.

С разрешения пользователя скачана та же версия Nova Kemono v8.0. SHA256 проверен: `a643bf5963bde8be779f07df5c5349921ae84d7dc2fc5a1bcd673eee07f4b151`. Он совпал с карточкой Stability Matrix и [публичным файлом с фиксированной ревизией](https://huggingface.co/SiE69/Illoustrious_Checkpoint_Collection/blob/1ef1a7b03d294e57c84b3efc96ccfe833987a5d8/novaKemonoXL_v80.safetensors). Проверенный файл установлен под прежним именем. Повреждённый файл сохранён в старом `ComfyUI/custom_nodes/comfyui_dashboard/.cache/baseline/novaKemonoXL_v80.corrupt.safetensors`.

Один и тот же официальный граф с тем же seed дал шум на старых весах и нормальный портрет на проверенных. HAGS и другие системные настройки Windows не менялись. Диагностические `--disable-dynamic-vram`, `--fp32-unet`, `--fp32-text-enc` удалены из окончательного запуска; v_prediction не добавлен в рабочий рецепт. FP32-прогон старых весов отменён из-за тяжёлого вытеснения из VRAM, его нельзя считать завершённой проверкой. Причина появления нулей в старом файле не установлена.

## Импорт LoRA и моделей

В заголовке «Стек LoRA» находится компактная кнопка «Импорт»: нажатие открывает выбор файла. Зона DnD под заголовком появляется только при перетаскивании файла на страницу и скрывается после ухода или отпускания файла. Можно также перетащить один `.safetensors` на страницу. Оригинал в «Загрузках» сохраняется.

Панель читает заголовок, определяет LoRA / полный checkpoint / отдельные diffusion weights и базовую модель по явным метаданным. Названия Illustrious/Pony в имени — только подсказка с запросом проверки. Категория назначается автоматически только из явного поля `category` / `modelspec.category`; остальные значения выбирает пользователь. При полном распознавании импорт начинается сразу. Допустим файл до 32 ГБ и заголовок до 16 МБ.

Каталоги берутся из зарегистрированных путей ComfyUI. В этой установке используются общие `Data/Models/Lora`, `StableDiffusion`, `DiffusionModels`. LoRA сохраняются в `Категория/База/имя.safetensors`, модели — в `База/имя.safetensors`. Старые файлы не перекладываются. Веса проверяются библиотекой safetensors без загрузки на GPU; готовый файл публикуется атомарно без перезаписи. После сохранения списки обновляются. Совместимость отдельной diffusion model с генератором зависит от поддерживаемого рецепта, сам импорт рецепт не добавляет.

Проверки импорта: `../../Data/Packages/ComfyUI/venv/Scripts/python.exe tests/test_import.py`, `../../Data/Packages/ComfyUI/venv/Scripts/python.exe tests/test_server.py`; сценарий DnD в браузере — `tests/import.browser.js`.

## Меню настроек

Две видимые вкладки: «Изображение» и «Обработка». Персонаж и LoRA находятся на вкладке «Изображение». На компьютере вкладка «Изображение» использует три равные колонки: модель, формат и персонаж в первом ряду; LoRA — отдельным рядом на всю ширину с карточками по той же сетке. У карточек общие края и промежутки 16 px. «Обработка» использует две равные колонки. На телефоне остаётся один столбец. Высота рабочей области ограничена окном, панель настроек прокручивается независимо. Семплер и планировщик расположены рядом. Общий аккордеон обработки удалён: её параметры появляются рядом с включённой функцией. Переключение вкладок сохраняет введённые значения; импорт перетаскиванием открывает вкладку «Изображение». Колесо над числовыми настройками и ползунками меняет значение с учётом шага и границ поля.

## Свои форматы изображения

Плитка «+» открывает создание формата с названием и размерами; по умолчанию подставлены текущие ширина и высота. У каждой плитки есть карандаш слева сверху и удаление справа сверху: на компьютере они появляются при наведении или фокусе, на телефоне видны постоянно. Иконка и сокращённое соотношение сторон вычисляются из размеров. Допустимы 256–2048 px с шагом 8. Редактирование активного формата обновляет текущие размеры; удаление после подтверждения сохраняет их. Удалять и редактировать можно также исходные форматы. Список хранится отдельно в localStorage этого браузера (`prism_image_formats`) и не заменяется при выборе пресета генерации или кадра истории.

## Seed и небольшая вариация

При переходе со случайного seed на фиксированный панель берёт seed выбранного кадра в предпросмотре; по умолчанию это последний результат. Введённое вручную число сохраняется. Если истории ещё нет, создаётся новое число. В общей сетке нужно выбрать кадр для точного копирования его seed. «Повторить кадр» отправляет только сохранённый граф этого кадра, «Повторить серию» — всю серию.

Сворачиваемая «Вариация» содержит второй seed (`random` или `-1` — новый при запуске) и силу 0–1. Изменение силы выше нуля фиксирует базовый seed. Для небольших изменений можно начать с 0.05–0.15; эффект зависит от модели, промпта и семплера. Оба seed и сила сохраняются в снимке задания и метаданных PNG; «Взять параметры» восстанавливает фактический seed вариации. Старые снимки без вариации восстанавливаются с силой 0.

При силе 0 используется прежний KSampler. При силе выше 0 узел PrismVariationNoise смешивает два поля начального шума методом SLERP и передаёт результат стандартному SamplerCustomAdvanced. Последующие Hires/FaceDetailer сохраняют прежнюю логику. Это механизм вариации по образцу Forge, а не обещание побитового совпадения изображений разных движков. Исходники Forge: https://github.com/lllyasviel/stable-diffusion-webui-forge/blob/main/modules/processing_scripts/seed.py и https://github.com/lllyasviel/stable-diffusion-webui-forge/blob/main/modules/rng.py .

## Квадратные серии 1 / 4 / 9

Количество выбирается трёхпозиционным ползунком в обоих режимах. Один запуск создаёт один кадр либо серию 2×2/3×3. Каждый кадр вычисляется отдельной веткой графа с batch_size=1; это сохраняет его seed и позволяет повторить один кадр отдельно. Модель и общие вычисления переиспользуются кэшем ComfyUI. Это не один тензор из девяти изображений.

Без вариации используются seed, seed+1 и так далее. С вариацией базовый seed остаётся общим, а меняется seed вариации, как в Forge (modules/processing.py, all_seeds/all_subseeds). Метка batchLayout=square-v1 закрепляет эту схему в истории. Порядок изображений определяется выходами SaveImage в графе, а не порядком ответа сервера.

Предпросмотр автоматически показывает всю сетку. Клик по ячейке открывает кадр с его параметрами; «Сетка» возвращает общий вид. «Взять параметры» у кадра устанавливает количество 1 и оба seed. В режиме сетки скачивается PNG-коллаж, в режиме кадра — оригинальный файл. Очень большие коллажи уменьшаются до стороны не более 8192 px и площади 32 Мп для ограничения памяти браузера; исходные файлы сохраняют разрешение. В localStorage хранятся ссылки и параметры, а не PNG-коллаж.

Ранее описанные GPU-прогоны batch=2 относятся к прежней реализации. Новый механизм проверен через backend на CPU-кадрах 1/4/9 и тестами графа; диффузионный прогон на GPU не выполнялся.

## Пресеты модели

Пресеты находятся в карточке «Модель генерации» и хранятся в `data/model-presets.json` (предыдущая запись — `.json.bak`). Встроенных наборов нет. Состав: checkpoint, шаги, CFG, семплер, шедулер, переключатель дополнительных параметров, Clip Skip и VAE. Промпты, персонаж, стек LoRA, seed, формат, серия и обработка в пресет не входят.

«Сохранить как новый» создаёт именованный набор. После изменения параметров появляется статус «Изменено»: можно явно сохранить изменения или вернуть сохранённые. Удаление требует подтверждения и сохраняет текущую форму. Выбранное имя восстанавливается после перезагрузки. Старые пользовательские браузерные пресеты переносятся только в части параметров модели; исходные снимки остаются в браузере. При совпадении имён приоритет у JSON.

Запись атомарна и защищена версией от потери изменений другой вкладки. Ошибка видна рядом с пресетами. Кнопка обновления списка рядом с заголовком модели ищет новые файлы на диске и показывает число найденных checkpoint-моделей и новых записей; она также обновляет списки LoRA, VAE и апскейлеров.

## Библиотека LoRA / Civitai

Внизу вкладки «Изображение» находятся карточки установленных LoRA: превью, имя, версия, база, автор и триггеры. Есть поиск по имени/автору/триггеру/тегу и фильтр базовой модели. Нажатие на превью открывает подробности с описанием, тегами и ссылкой Civitai. Триггер можно скопировать. «Добавить LoRA» подключает конкретный файл в текущий стек; вес регулируется там. Уже подключённая карточка отмечена.

При открытии читаются соседние `.cm-info.json` и `.preview.jpeg/.jpg/.png/.webp`. Кнопка обновления на карточке находит версию Civitai по полному SHA256 локального файла, загружает сведения о модели и сохраняет результат в `.cache/civitai`. Модель не загружается в GPU и никуда не отправляется; наружу передаётся только хеш. Локальные sidecar-файлы не переписываются. Превью, полученное от API, отображается по URL Civitai; локальное превью приоритетнее. Ошибка сети/404 сохраняет имеющиеся данные и видна в карточке. Обновление метаданных выполняется по одной LoRA за раз.

Публичный поиск по хешу работает без API-ключа: https://github.com/civitai/civitai-developer-docs/blob/main/site/reference/model-versions.md . Для закрытых ресурсов доступ может быть ограничен; ввод ключа пока не добавлен, поскольку для установленной библиотеки он не понадобился.

Карточки библиотеки и окно подробностей содержат кнопку «Копировать кейворды»: копируется полный список, даже если текст карточки сокращён. При успехе кнопка показывает «Скопировано»; если доступ к буферу запрещён, открывается поле для ручного копирования. Категории библиотеки берутся из первого каталога относительного пути LoRA, как при импорте; переключатели показывают количество файлов и работают совместно с поиском и базовой моделью. Категория также подписана на карточке.

Копирование кейвордов оформлено компактной иконкой из общего SVG-набора рядом с текстом. После успешной записи в буфер она на 1,5 секунды меняется на галочку; область нажатия — 28×28 px на компьютере и 44×44 px на телефоне. Такой же элемент используется в подробностях LoRA.

Кнопки панели используют компактную плотность: текстовые — от 32 px, иконки — 28 px, подписи — 12 px; плитки форматов — 52 px. До 1100 px и при сенсорном указателе области нажатия остаются не меньше 44 px. Кнопки действий больше не растягиваются на всю ширину пустой карточки.

На карточке LoRA три действия объединены в нижний ряд иконок: «+» (добавить), копирование всех кейвордов и обновление с Civitai. После добавления «+» становится галочкой и блокируется; копирование временно показывает галочку. В подробностях остаётся подписанная кнопка добавления.
